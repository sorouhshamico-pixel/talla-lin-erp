# Phase 50 — Saved View Management Enhancements

## الهدف

توسيع إدارة العروض المحفوظة للتقارير بحيث يستطيع المستخدم التعامل مع العرض المحفوظ من صفحة الإدارة بشكل كامل، وليس فقط حفظه أو حذفه.

تشمل المرحلة:

- فتح صفحة تعديل للعرض المحفوظ.
- تعديل اسم العرض وحالة العرض الافتراضي.
- تحسين عرض الفلاتر داخل صفحة التعديل.
- تعديل قيم الفلاتر المحفوظة.
- نسخ عرض محفوظ إلى نسخة جديدة.
- تطبيق العرض المحفوظ مباشرة لفتح التقرير بفلاتره.
- حماية كل العمليات حسب مالك العرض المحفوظ.

## النطاق الوظيفي

### صفحة تعديل العرض المحفوظ

تمت إضافة صفحة تعديل مستقلة لكل عرض محفوظ عبر المسار:

```text
reports.saved-views.edit
```

وتدعم الصفحة:

- عرض اسم العرض المحفوظ.
- تعديل الاسم.
- تعيين العرض كافتراضي للتقرير.
- عرض التقرير المرتبط بالعرض.
- عرض الفلاتر المحفوظة.
- تعديل قيم الفلاتر المحفوظة.
- الرجوع إلى صفحة إدارة العروض المحفوظة.

### تحديث العرض المحفوظ

تمت إضافة مسار تحديث عبر:

```text
reports.saved-views.update
```

وتدعم عملية التحديث:

- التحقق من اسم العرض.
- تحديث حالة `is_default`.
- عند جعل عرض معين افتراضيًا، يتم إلغاء الافتراضية عن باقي عروض نفس المستخدم ونفس التقرير.
- تحديث مصفوفة `filters`.
- حذف الفلاتر ذات القيم الفارغة عند الحفظ.
- منع المستخدم من تعديل عروض مستخدم آخر.

### تحسين عرض الفلاتر

بدل عرض المفاتيح الخام فقط مثل:

```text
customer_id
supplier_id
branch_id
aging_bucket
payment_status
```

تم تحسين العرض ليظهر بتسميات مقروءة مثل:

```text
العميل
المورد
الفرع
شريحة العمر
حالة الدفع
```

كما تم تحويل بعض القيم الفنية إلى قيم عربية أوضح، مثل:

```text
without_due_date => بدون تاريخ استحقاق
not_due => غير مستحق
paid => مدفوعة
unpaid => غير مدفوعة
```

### تعديل الفلاتر

تم تحويل الفلاتر في صفحة التعديل إلى حقول قابلة للتحرير.

عند حفظ التعديل:

- يتم حفظ القيم الجديدة داخل `filters`.
- يتم الاحتفاظ بنفس مفاتيح الفلاتر الموجودة.
- يتم حذف أي فلتر تصبح قيمته فارغة.
- لا يتم تغيير `report_key`.

### نسخ العرض المحفوظ

تمت إضافة إجراء نسخ عبر:

```text
reports.saved-views.duplicate
```

ويقوم بإنشاء عرض جديد بنفس:

- المستخدم.
- التقرير.
- الفلاتر.

مع اختلافات مقصودة:

- الاسم يصبح باسم العرض الأصلي مع لاحقة `- نسخة`.
- النسخة لا تكون افتراضية حتى لو كان الأصل افتراضيًا.
- يتم قص الاسم إلى حد آمن لا يتجاوز 120 حرفًا.
- لا يمكن نسخ عرض محفوظ يخص مستخدمًا آخر.

### تطبيق العرض المحفوظ

تمت إضافة إجراء تطبيق عبر:

```text
reports.saved-views.apply
```

ويقوم بما يلي:

- التحقق من ملكية العرض.
- بناء رابط التقرير المرتبط من `report_key`.
- تمرير الفلاتر المحفوظة كـ query string.
- إعادة توجيه المستخدم مباشرة إلى التقرير بالفلاتر.
- إعادة المستخدم إلى صفحة الإدارة برسالة مناسبة إذا كان التقرير غير معروف.

## قيود مقصودة

- تعديل الفلاتر يتم على المفاتيح الموجودة داخل العرض المحفوظ فقط.
- لا يتم تغيير `report_key` من صفحة التعديل.
- النسخة الجديدة لا تصبح افتراضية تلقائيًا.
- تطبيق العرض يعتمد على `REPORT_ROUTES` داخل `ReportSavedViewController`.

## نتيجة المرحلة

بعد هذه المرحلة أصبحت إدارة العروض المحفوظة أكثر اكتمالًا، حيث يستطيع المستخدم:

- تعديل العرض.
- تحسين فلاتره.
- نسخ العرض.
- تطبيقه مباشرة.
- إدارة الافتراضي بشكل آمن.
